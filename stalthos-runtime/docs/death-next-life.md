# Death and explicit next life: connected working draft

Connected mode follows the existing Lifecycle calendar into Dead and records the
old hero through StalthosState::heroDied. Movement, contact and needs stop. A
readable message says that the world continues and offers **N** for a new life.
N must be pressed after death; a held key from before death does not continue.

The explicit handoff chooses an unused identity, avoiding active/retained/dead IDs
and every current NPC, and allocates a separate contact session from the existing
native session allocator. It starts a new age-zero individual of the same species
at the existing supported position. Only hero-local needs, lifecycle, intent,
perception, rest/drink controller, peer link, wetness and pending contact/destination
state reset. Calendar, weather, retained residents, resources and history continue.
The previous ID remains dead/excluded. This is a session-local continuation;
original saved-mode successor behavior and connected save refusal remain intact.

`Run-ConnectedWorld.ps1 -DeathNextLifeProbe -Duration 18` supplies a labelled Old
age six calendar seconds from death, thirst for each individual, noon rendering,
dead-body movement attempt, explicit synthetic N action at physical10, and new
body movement at12..14. The normal loop uses actual calendar and ordinary input.
These fixtures do not establish human keyboard acceptance or elapsed lifespan.

The body presentation is reused at the same supported position. No corpse model,
newborn anatomy, kinship, eligible offspring selection or connected persistence
is implemented. Fresh hatchling state uses the existing shared juvenile asset.
These are logged draft limits; do not polish them before the next subsystem.
