# Distance driven Wicked creature playback

`Run.ps1 -Creature <glb>` now requires `-CreatureAnimationMetadata <json>`. The JSON must contain a finite positive `duration_s` and measured `stride_length_m`, either at the top level or under `walk_cycle`; the stride may be nested under `terrain_contact_height`. For the aligned reference walk, these are 2.0 s and 0.16128 m. Missing or invalid metadata is rejected before launching the runtime.

The host validates the imported Wicked animation length against the report duration with a 5% tolerance, accommodating a one-frame inclusive export endpoint. `LocomotionClip` advances from signed horizontal body displacement after the host clamps X/Z to playable bounds. The host assigns `animation.start + phase` and pauses the animation before each `app.Run()`: Wicked re-evaluates a paused animation when its timer changes, while its animation update system advances time only for playing components. Idle and dead actors retain their phase. Backward body travel feeds negative distance and wraps phase through `LocomotionClip`.

During import, the host identifies the non-skin animated transform that is an ancestor of all animated targets. It rejects an ambiguous or missing root and excludes every entity in imported armature bone collections from candidacy. It removes only that transform's translation channel, preserving its imported initial local transform and every animated bone translation, rotation, and scale channel. On the aligned source this target is `creature_rig`; `spine_00` is a skin bone and remains animated. The root-motion channel in the source GLB changes +0.161280 m on authored +X across the clip, matching the report's 0.16128 m stride. The host's facing parent maps this longitudinal axis to world +Z.

The runtime receipt reports the removed-channel count and target name, imported clip length, signed body distance, expected and actual clip phase, evaluated local pose delta, and animation playing-frame count. `animation_playing_frames: 0` is expected for this adapter: pose evaluation is triggered by the manually changed paused timer. A nonzero local pose delta confirms that evaluation occurred. These signals do not establish foot locking, tail clearance, final visual quality, or target-hardware performance.

For a bounded reverse playback check, use `Run.ps1 -DiagnosticReverseWalk`. For ordinary interactive backward motion, hold `S`. Existing lifecycle, needs, save, scenery, and camera behavior remains in the same host loop.
